# Disk map

Scan the Mac read-only, open a local viewer, and stay connected as the user's agent. The user asks about map regions in the viewer's Chat; **you** answer them. Cleanup happens only after the user confirms the exact manifest in the viewer. You never delete anything yourself.

## Hard rules

1. **You are the chat backend.** Never start another agent, model API, `claude -p`, `codex exec`, or any replacement process to answer the viewer. Never edit host settings, MCP config, sandbox or approval modes.
2. **Never delete, move or empty anything with your own tools.** The runtime executes only manifests the user confirmed in the viewer. A "yes" in Chat is not consent.
3. **Do not bulk-read contents.** Inspect metadata (names, sizes, dates, `ls`, `ps`, `git check-ignore`). Never read conversations, browser databases, credentials, keychains or mail. When one small sample is needed to answer a question, say what you read and why.
4. **Evidence, not names.** "cache", a large size, or an old date never makes something safe. Follow [references/assessment.md](references/assessment.md).
5. **Keep host approvals intact.** If the host asks permission for a command, let it. If the local runtime cannot run (cloud sandbox, container, remote host), stop and explain; do not scan a different machine.

## Requirements

macOS, Node.js 22+, local command execution on the Mac being inspected, and a browser. No npm install, API key or configuration change. Host specifics: [references/host-compatibility.md](references/host-compatibility.md).

## 1. Start

Use the invocation language for `--locale` (`ja` for Japanese, otherwise `en`) and for every reply.

```bash
node <skill-dir>/scripts/disk-map.mjs start --locale en --open
```

- Default root is the data volume (`/System/Volumes/Data`). For a narrower scan pass `--root /Users/<you>/Projects`.
- The JSON output has `session` (absolute path to the private session file), `viewerUrl` (one-use link), and `next` (the exact next command). If `--open` is unavailable, give the user the `viewerUrl` once; it stops working after the first page load.
- Exit code 2 means preflight failed (not macOS, Node too old, root unreadable). Report the `message` and stop.

## 2. Service loop

Repeat until the session ends:

```bash
node <skill-dir>/scripts/disk-map.mjs next --session <session> --timeout 25
```

| Output | Do this |
|---|---|
| `{"type":"idle"}` | Call `next` again immediately. |
| `kind: "scan-complete"` | Assess `payload.candidates` and the relevant `payload.largest` entries (step 3). |
| `kind: "chat"` | Answer `payload.text` about `payload.candidates` (step 4). |
| `kind: "investigate"` | The user pressed *Investigate further* on a review item: investigate, then `assess` it again and `respond`. |
| `type: "session-ended"` (exit 3) | Run `stop`, then summarise the reports to the user. |
| exit 4 (unreachable) | The runtime stopped. Tell the user; offer to start a new session. |

- If an investigation takes longer than ~40 s, run `heartbeat --session <session>` so the viewer keeps showing you as connected. The viewer marks you disconnected 60 s after your last call and pauses new cleanup plans.
- A message with `redelivered: true` was not answered before its lease expired; answer it once.
- Keep servicing the loop between your own tool calls. Do not end your turn while the user is still using the viewer unless the host forces it; if it does, tell the user how to resume (ask you to "continue the disk-map loop").

## 3. Assess

For each candidate, collect evidence with read-only commands, then write a JSON file (absolute path, for example next to the session file) and submit it:

```bash
node <skill-dir>/scripts/disk-map.mjs assess --session <session> --file /abs/path/assess-1.json
```

```json
{
  "scanId": "<payload.scanId>",
  "revision": 0,
  "messageId": "<the scan-complete messageId>",
  "assessments": [
    {
      "candidateId": "<uuid>",
      "risk": "safe",
      "purpose": "Next.js build output",
      "reason": "Git-ignored build output; regenerated by next build.",
      "consequences": ["The next build is slower once."],
      "evidence": [
        { "kind": "local", "reference": "git check-ignore -q exit 0; no process has the project open", "checkedAt": "2026-10-18T10:00:00Z" },
        { "kind": "documentation", "reference": "https://nextjs.org/docs/app/api-reference/cli/next", "checkedAt": "2026-10-18T10:00:00Z" }
      ],
      "recipe": "build-output",
      "question": null
    }
  ]
}
```

- `safe` needs a permanent-cleanup recipe (`build-output`, `derived-data`, `app-cache`, `npm-cache`, `pnpm-store`, `uv-cache`), local **and** documentation evidence, and consequences. The runtime re-checks path rules, Git-ignore status and running processes; anything that fails becomes `review`.
- Uncertain ownership or personal data → `review` with a plain `question` the user can answer (Keep is the default; Trash only after they choose it).
- Credentials, settings, active work, source, VM/Docker disks, app bundles → `protected`. The runtime already protects many of these; never try to argue past it.
- The response lists each result's effective `risk` and `selected` state. If `stale-revision` is returned, run `status` and use the current revision.

## 4. Answer chat

Write the reply to a file and send it with the message ID and current revision:

```bash
node <skill-dir>/scripts/disk-map.mjs respond --session <session> --file /abs/path/reply-1.json
```

```json
{ "messageId": "<payload messageId>", "revision": 0, "text": "This is Xcode DerivedData for an old project…", "candidateIds": ["<uuid>"] }
```

Answer in the user's language, in plain text, with what the folder is, what removing it would cost, and what you checked. If your answer changes the assessment, also run `assess`. Never instruct the user to run destructive shell commands; point them to the viewer's checkboxes, Review button and Clean Up.

## 5. Stop

```bash
node <skill-dir>/scripts/disk-map.mjs stop --session <session>
```

`stop` waits for a running operation to record its outcome, then writes reports. Summarise for the user: files in `reports/` (summary, operations JSONL/CSV, skipped/failed list, read-only HTML snapshot), succeeded/skipped/failed counts, bytes moved to Trash (not yet freed), and the observed free-space change. Mention that Trash is never emptied automatically.
