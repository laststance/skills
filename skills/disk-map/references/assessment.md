# Assessment rules

An assessment is a proposal. The runtime applies its own eligibility rules and can only make an item *less* permissive than you proposed.

## Evidence

| Kind | What counts | What does not |
|---|---|---|
| `local` | Output you observed on this Mac: `git -C <repo> check-ignore -q -- <path>` exit 0, `ps` shows the owner app is not running, the folder is the resolved `npm config get cache`, file dates/counts from `ls`/`stat` | A folder name, a size, an age, or "usually safe" |
| `documentation` | An `https://` page from the tool or platform that says the data is regenerable (for example the recipe links below) | Blog posts that only recommend deleting; private filenames in a search query |

Search documentation with generic product questions only ("Xcode DerivedData safe to delete"), never with private paths or file names.

Do not bulk-read file contents. Never read conversations, browser profiles (Cookies, Login Data, Local Storage, IndexedDB), credentials, keychains, mail or messages.

## Risk levels

| Risk | When | Viewer behavior |
|---|---|---|
| `safe` | A permanent-cleanup recipe matches the exact path, local + documentation evidence, consequences stated, executor checks pass | Preselected (unless the user unchecked it) |
| `review` | Personal or uncertain data: old recordings, downloads, model files, inactive agent conversation archives, `node_modules`, unknown app data | Unchecked; the user answers a question (Keep / Move to Trash / Investigate further). Trash only |
| `protected` | Credentials, settings, active work, source, Docker/VM disks, app bundles, browser site data | Visible with the reason; no cleanup control |
| `blocked` | Incomplete scan, missing tool, unsupported location | Visible with the reason; no cleanup control |

The runtime protects these regardless of your proposal: credentials (`.ssh`, `.gnupg`, `.aws`, `.kube`, Keychains), browser site/auth stores (Cookies, Login Data, Sessions, Local Storage, IndexedDB, Service Worker), `~/Library/Preferences`, Mail/Messages/Safari/iCloud, the Chrome and Chrome Canary profiles, dotfiles in your home, agent settings (`~/.claude.json`, `~/.claude/settings.json`, `~/.codex/auth.json`, `~/.codex/config.toml`), repository and worktree roots, everything inside a Git work tree except `.next`, `.turbo` and `node_modules`, `*.app` bundles, Photos/Music libraries, Docker/VM disks, anything outside your home, folders that contain any of these, broad roots (`~`, `~/Library`, `~/Library/Caches`, `~/Library/Application Support`, `~/.cache`, …) and whole application data folders. A generic "yes" in chat cannot change this.

### Examples

| Path | Proposal | Why |
|---|---|---|
| `~/code/shop/.next` (Git-ignored, no dev server open) | `safe`, `build-output` | Regenerated by `next build`; the runtime verifies Git-ignore and open files |
| `~/Library/Developer/Xcode/DerivedData/Shop-abcdefghijklmnopqrstuvwxyzab` | `safe`, `derived-data` when Xcode is not running | One project folder only, never `DerivedData` itself |
| `~/Library/Application Support/Cursor/Cache` with Cursor quit | `safe`, `app-cache` | Verified leaf (see below) |
| `~/Library/Caches/com.tinyspeck.slackmacgap` | `review` | Leaf not verified on the reference Mac; Trash only |
| `~/.codex/archived_sessions` | `review` | Conversation history; only the user can decide |
| `~/Downloads/old-installers` | `review` | Personal files |
| `~/Library/Containers/com.docker.docker` | `protected` | VM disk; lifecycle operations are out of scope |
| `~/Library/Application Support/Google/Chrome/Default` | `protected` | Contains Cookies/Login Data |
| `~/Library/Caches/com.google.SoftwareUpdate` | `review` | Google updater caches are separate visible candidates, never hidden |

## Recipes

The executor runs only these fixed operations. You cannot supply commands, argv or paths for them.

| Recipe | Exact target | Operation | Usage check |
|---|---|---|---|
| `build-output` | A `.next` or `.turbo` folder inside a Git work tree that `git check-ignore` reports ignored | Staged permanent removal of that folder only | No open file or working folder inside the project |
| `derived-data` | One `<Project>-<28 letters>` folder directly inside `~/Library/Developer/Xcode/DerivedData` | Staged permanent removal | Xcode, `xcodebuild`, `XCBBuildService`, `swift-frontend` not running; no open files |
| `app-cache` | A verified leaf in the table below | Staged permanent removal | Owner app not running; no open files |
| `npm-cache` | `<npm config get cache>/_cacache` | `npm cache clean --force --cache <root>` | No `npm`/`npx` process |
| `pnpm-store` | The path printed by `pnpm store path` | `pnpm store prune --store-dir <store-dir>` (removes unreferenced packages only; represented bytes are not a reclaim promise) | No `pnpm` process |
| `uv-cache` | The path printed by `uv cache dir` | `uv cache clean --cache-dir <dir>` (bounded timeout) | No `uv` process |
| `trash` | A user-reviewed, non-protected item owned by you on the same volume as the Trash | Move into `~/.Trash/disk-map-<operation-id>/` | No open files |

Tools must be on `PATH` (npm 7+, pnpm 7+, uv). Missing or incompatible tools make the candidate `blocked`/`review`.

Documentation: [Next.js CLI](https://nextjs.org/docs/app/api-reference/cli/next), [Turborepo caching](https://turborepo.com/docs/crafting-your-repository/caching), [Xcode build system](https://developer.apple.com/documentation/xcode/build-system), [npm cache](https://docs.npmjs.com/cli/commands/npm-cache), [pnpm store](https://pnpm.io/cli/store), [uv cache](https://docs.astral.sh/uv/concepts/cache/).
