# 判定・継続・差分

この仕様は既存の読み取り専用・秘密保護・外部送信の境界を変えない。stateの継続情報・公開詳細キャッシュ・差分の基準はローカル専用で、共有サービスへ送らない。

## ユーザーごとの探索ルート

`~/.local/state/mac-security-sweep/state.json`の`scanRoots`を使用する。未設定時だけ`~/Projects`、`~/repository`、`~/work`を使う。既存stateの取得カーソルや差分の基準は保持し、次のパス・区分のみを追加できる。

**読むだけの設定形状**。実際の編集は [設定資料](configuration.md) に従い、既存stateの対象キーだけをmergeする。

```json
{"scanRoots":[{"path":"~/Projects","scope":"personal"},{"path":"~/work","scope":"work"}]}
```

ルートは最大20件、ホーム配下の通常のプロジェクト領域に限定する。ホーム全体・隠し認証領域・Library・Applications・親参照・URL・認証値らしい表記は受け入れない。不正な指定はwork前に終了値64で拒否する。存在しないrootは未確認として記録する。実測パスと個人/仕事の所有範囲はローカルの証拠にだけ保持し、公開スキルへ埋め込まない。

## 告知と証拠

- GitHubの`advisoryType: malware`、OSVの`MAL-`識別子を保持し、通常の脆弱性と区別する。悪性配布のロック一致は実行や窃取の確定ではない。出典不明の「malicious」という見出しだけでは悪性配布へ格上げしない。
- 四段階の判定に加え、ロック/グローバル記録、実物の版、親プロジェクトの稼働を表示する。実物確認は影響版npmのpackage.jsonのみ、最大1,200候補・統合runnerの共有残り予算内。名前・版・パス以外のフィールドを破棄し、コードをimport/実行しない。モノレポのpackage.json所在は棚卸し時に最大5,000件を記録する。
- Node待受PIDの実体確認は最大12PID・全体30秒。cwdは対象プロジェクト/既知OpenClaw領域、txtは既知Node保存先だけ保存する。LaunchAgentの引数・既知OpenClawラッパーはメモリ内で固定Nodeパスだけ抽出し、引数・環境変数・ラッパー本文を保存しない。
- 優先順は固有IOC、悪性配布、悪用確認、深刻度、親プロジェクト稼働、実物確認、仕事領域、更新日時。深刻度未取得は未評価のまま。取得済み詳細からCVEのKEV一致を確認し、撤回された告知は陽性に追加しない。

## 上限と再開

- ロックは1回400件。前回未処理を先に、次に変更・新規、稼働中プロジェクトを優先する。バックアップやQA保存物も除外せず後へ回す。stateにだけあるパスは対象に追加しない。
- パッケージ照会は1回15,000種類。同じ名前・版・証拠元の集合が変わらず、24時間以内に継続している場合だけ成功済み照会と陽性結果を引き継ぐ。対象変更、またはqueryと告知詳細の一巡完了後は再照会する。詳細が残る間は検証済み24時間以内の全ページIDを保持する。失敗・追加ページ未取得は未確認として残す。
- 告知詳細は1回80IDまで。統合runnerの共有残り予算内で取得し、他段階と保存時間を共有する。既知の悪性配布・高深刻度等を優先し、その後は未取得IDを先にする。公開詳細のキャッシュは7日以内かつ告知未更新の場合だけ使用する。未取得ID・失敗IDを持ち越す。
- CLIの`scan-packages.mjs --state <path>`はstateを読むだけで、継続情報を標準出力へ返す。runnerだけがレポート保存後に`packageContinuation`、`advisoryContinuation`、`assessmentSnapshot`をstateへ記録する。旧stateに各項目がなければ初回として始める。

## ニュースと更新候補

- 構造化告知は名前・ecosystemで一致させる。一般文のthree/connect/Code等から導入を推測しない。パッケージとして明示された言及とブラウザ拡張の調査記事は「確認候補」とし、対象ID・版・配布元を確認する。他OSのChromeリリースはMacの影響版として扱わない。
- Appleの取得済み公式リリース表を期間外も最大120件保持し、Xcode/Safariの更新候補と照合する。未到達・比較不能は「可能性あり」。OS適合性・CVEの影響開始版は本文で確認する。未知のベンダーの版体系へ一般化しない。
- 検証済み固定ルールは最終検証から30日超で出典再確認を要求する。古い範囲だけで最新の「影響なし」を継続しない。自動でルールやIOCを書き換えない。

## 差分と完了状態

- 陽性記録のキーが同じなら継続、初めてなら新規。旧stateには基準がないため初回は新規として扱う。
- 依存の解消は、以前のすべての証拠元ロックの再解析がcompleteで、OSV照会が全件・追加ページなしで完了した場合に限定する。ファイルが消えた、上限で未走査、読取失敗、解析不完全なら確認不能として基準を持ち越す。
- 悪性配布・確定IOCは、現在の拡張や版が対象外になっただけでは解消にしない。対応完了の判断には人による実行痕跡・永続化等の確認が必要。
- `complete`は対象範囲の巡回完了、`complete-with-exclusions`は方針による対象外のみが残る状態、`partial`は持越し・取得失敗・追加確認・本文未確認が残る状態。どれもMacの無侵害保証ではない。ニュースの未取得期間は従来どおり情報源別カーソルを保持する。

## 開発時の回帰確認

スキルrootで入力する `node --import ./tests/deny-network.mjs --test tests/*.test.mjs`で架空の棚卸し・公開告知・一時ファイルを使う。通信はスタブに固定し、実機スキャン・既存stateの書換え・パッケージ追加はしない。安全境界の既存テストと、悪性配布/ニュース分類/再開/重要度/実物と稼働/更新候補/差分の観測可能な振る舞いを確認する。

## 世代と有限page

探索のfiles pageとfrontierを分離し、同じfile identityが解析/照会/詳細まで完了したことを検証済み世代で確認してから次pageへ進む。以前のpageの陽性は差分基準と私有レポートに保持する。別pageだけを調べた回を全件の新鮮な再検査と呼ばない。未確認の以前の陽性は冒頭とcoverageにも残す。

重大度は方式・元値・出典を保持し、未計算vector/unknownをLOWより低優先度へ下げない。aliasだけを推移結合して告知数・場所/版を含む影響先数を別表示する。Homebrew upstream/関連告知はaliasではない。
