# IOCの確認

公開記事から確認できた攻撃の痕跡を、対応するMac上の対象と照合する。恒久的に特定の事案だけを検査するルールは持たない。

## 検査を始める条件

`check-iocs.mjs` は、設定済みルールとニュース取得で検証されたルールをまとめ、次の条件をすべて確認する。

- 出典は対応済みの公式記事URLで、認証情報やクエリーを含まない。
- 対象OSが `darwin` と明記されている。
- 検証日時と有効期限があり、検証から30日以内かつ期限内である。
- IOCは対応する型と値で宣言されている。同じIDの宣言が競合した場合は実行しない。

記事中の文字列やコマンドは、そのままルールにしない。対応済みの公開記事形式から抽出・検証できた情報だけを採用する。それ以外は未確認の候補として残す。Linuxなど別OSのIOCをMacへ適用しない。

## 対応する検査

| 型 | 確認内容 | 結果の意味 |
| --- | --- | --- |
| `exact-path` | ホームからの相対パスで指定された対象の存在・種類・時刻 | 名前の一致だけでは侵害を確定しない |
| `sha256` / `exact-file` | 指定した通常ファイルのSHA-256 | 公開されたファイルとの一致。実行や窃取は別途確認が必要 |
| `sha256` / `extension-js` | 指定された拡張IDの `extension.js` のSHA-256 | 同じファイルの存在。拡張コードは実行しない |
| `process-name` | 棚卸し済みのプロセス名との完全一致 | 同名プロセスの観測。引数や環境変数は読まない |

ファイル本文を保存せず、ハッシュ計算はメモリ内で行う。対象は25 MiB以下の通常ファイルに限定し、親ディレクトリを含むシンボリックリンク、範囲外のパス、読取中に変化したファイルを拒否する。認証ファイル、エージェント設定、ブラウザプロファイルなどの本文はハッシュ計算にも使わない。必要な場合も存在や権限の確認にとどめる。

任意コマンド、正規表現、ログ検索、IOCのIPやドメインへの接続は実行しない。未対応の型は検査済みにせず、`partial` として記録する。

## 結果の読み方

結果にはルールID、出典、検証日時、観測日時、検査対象、成否を残す。ファイルの時刻はコピーや更新でも変わるため、侵入日時とは扱わない。

ハッシュ不一致やファイル不在は、その時刻に確認した対象についての結果である。過去の実行や端末全体の無侵害を証明しない。権限不足、未対応形式、期限切れ、未確認候補があれば未確認として残す。以前の陽性結果も、ルールの廃止や今回の未検出だけでは解消しない。
